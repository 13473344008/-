## 安全与业务上线阻断项

1. 先解决或重新明确验收范围：媒体正式输入入口、Published Clone、普通 Published→Draft 的产品边界。T12 §42 只授权本地 V2 夹具，不等于生产编辑流程。
2. 完整图片冻结、损坏图片拒绝、图片备份恢复和后台独立访问须补测。空 assets 清单的 Hash 自洽不能当图像链路通过。
3. 通用 `pnpm check:api` 当前有 4 处模型解析/匹配诊断，`test:ci` 未全绿。实际业务 API 已回归，但工具结果须修复或明确归类，不能隐去失败。
4. 当前安全图片处理仅 PNG/JPEG→PNG，不承诺 PDF/WebP；媒体扫描与上传边界不能靠静态 Schema 代替。
5. SQLite 在本地单实例短事务与本轮五请求竞争下可用；不承诺大量写入、多主、网络盘、断电恢复或生产性能。本机备份也不能抵御整机丢失。
6. 私有审核预览、公开静态、业务数据范围、直接 API 越权、撤权、日志脱敏、登录限流、生产验证码与备份读权限需目标环境验收。
7. Hash 是一致性校验，不是产品真实性认证或数字签名。商业资料与认证声明必须另行验收。

## 未来部署顺序（仅在单独授权后执行）

1. T12 全部必过项满足并人工验收；取得 T13 明确授权。确认测试/生产隔离及准确目标。
2. 只读核查服务器现况：OS/架构/磁盘、Docker、网络、现有 Caddy Compose 与 Caddyfile。用户应遮盖凭据；不索取 `.env`/私钥。记录既有站点验证基线，不能猜配置。
3. 准备独立后台目录、权限、持久存储、固定版本镜像/二进制、独立 Compose 与备份计划。无共享卷、Docker socket、Directus 数据挂载。
4. 备份当前独立项目（若已有），检查准确 DB 与 schema 版本。在测试专用 DB 执行新 Migration；历史 Migration 不改。记录输出，确认重复迁移与 integrity/FK。
5. 启动独立后台，再启动管理 UI；验证本地/内部 health、真实登录、角色、撤权、审核、发布、失败恢复与备份。health 不能只看进程或 HTTP200，应验证所需功能。
6. 独立公开 Nginx 加载只读公开根；通过内部连接验证 `/b/TEST-code`、Current JSON、历史 JSON、图片、404、缓存和后台停止后的访问。先测试环境，再考虑生产。
7. 发布使用版本化文件与可核对产物清单；确认 DB 与公开 Current/Manifest 一致，再交付候选部署证据。
8. **T14 另行授权**：涉及共享网络/Caddy 等变更先说明影响、验证、回退并取得明确确认。Caddy 配置先备份、校验，再经确认 reload 与回归既有站点。普通配置更新不得 down/up 共享 Caddy；网络/挂载变更不能假装 reload 生效。DNS/HTTPS/正式 QR 按独立授权执行，SSL 暂缓未解除。

## 部署回退方案（规划）

- 每个环境保留上一套应用二进制/镜像摘要、Compose、非敏感配置模板、DB 一致性备份、公开文件、私有 Manifest 和恢复映射。记录 schema 版本与兼容性。
- 应用回退先只停止本项目明确服务。确认旧二进制兼容现 DB；不兼容时用匹配的独立 DB 恢复副本先验证，不能盲目降级或修改历史 Migration。
- DB 与静态 Current 可能跨时间点：先只读比较头、版本、Hash、Manifest，未知或更先进静态头不自动被旧 DB 覆盖。必要时按已实现 Reconcile 判定；损坏不强制跳过。
- 若需要撤回已发布内容，应通过已验证历史生成新的回滚版本，保留所有历史；不能直接将 DB current 指回旧 ID，不能覆盖历史 JSON/资产。
- 静态服务回退只切本项目经验证的 frontend release/完整公开目录；保留历史引用文件，恢复后检查全部当前与历史路径、图片与缓存。后台回退不要求停止公开服务。
- 如后续经批准修改了共享入口，回退也仅恢复已备份的增量配置，经校验和确认 reload，并回归既有站点。不得全局 prune、删除共享网络/卷、重启 Directus 或重建 Caddy。
- 无法证明一致时保持最后一个已验证公开版本，隔离新的后台写入并留存证据；不能宣称同机服务故障绝不会影响其他站点。

本文件无可直接执行的服务器命令；没有实施任何 T13/T14 操作。
